## Context (all LIVE now)
- Enforced item economy is real: `take/drop/give/loot/unlock` work under `local_write_gate=:enforce`.
- **Possession** = a bursar **GREEN-TOKEN** (exclusive move-lock, holder-consent transfer, no pull/reclaim except admin force_release).
- **Durable ownership + write-authority** = **ZONE-STAMP**.
- They compose transactionally: `acquire-token → commit-restamp → transfer-token`.

## Design two verbs to FIT that model

### 1. MINE
Extract a raw item from a **resource node/vein** (a container-like world object with finite/regenerating yield) into the miner's inventory, under enforce. Resolve:
- Where the mined item's **zone-stamp** comes from (node's zone vs miner's).
- How a **green-token is MINTED** for a freshly-extracted item that has **no prior holder**.
- Node **depletion / regen** state (where it lives, how it's enforced).

### 2. SMITH / CRAFT
Combine N input items (**CONSUMED**) into a new output item per a recipe:
- Inputs must be **possessed** (holder green-tokens released/burned).
- Output **minted to the crafter** (new token + zone-stamp).
- **Recipe representation** — a doc? a verb attr? (pick, justify).
- **TRANSACTIONAL atomicity** — all-or-nothing; NEVER consume inputs if the craft fails.
