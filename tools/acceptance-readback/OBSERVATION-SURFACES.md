## Fail-closed recommendation

1. Preserve the held collector and unresolved fields. No public diagnostic route, Access policy
   change, service-token mint, secret read, live tail creation, application request, or container
   execution is justified by these findings.
2. If an already-loaded page is available to its actual human user, an explicit nonsecret export
   of only `organization_id`, origin and observation time can support org evidence, with provenance
   and staleness limits stated. It does not answer realm and is not permission to operate that session.
3. The only plausible existing remote avenue is a separately reviewed **stored telemetry read**,
   scoped to a named interval and exact deployed services. A new safe projector must retain only
   allowlisted identifiers, timestamp, deployment/request correlation, outcome, and corpus controls;
   no raw bodies, URLs with query/userinfo, headers, messages or assertions. Require evidence of
   configured/admitted organization and app-to-provider realm association, not merely matching
   traffic. Missing fields, no positive control, ambiguous correlation or stale deployment -> HOLD.
4. KV key listing and deployment metadata can corroborate identity/existence, but cannot substitute
   for that association. If retained telemetry does not contain the needed proof, the blocker remains
   real under these constraints. Report it rather than manufacture a fresh observation surface.
